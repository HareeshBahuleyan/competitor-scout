# Backend agent guide

These instructions apply under `apps/backend` and supplement the root `AGENTS.md`.

Read `docs/architecture/backend.md` before changing module boundaries, persistence, transactions, authentication, or job behavior. Read `docs/architecture/agent-runtime.md` before changing prompts, agent contracts, evidence validation, usage accounting, or run-state transitions.

## Layer responsibilities

- `api/`: HTTP routing, dependencies, status codes, query parameters, and response models. Keep routes thin.
- `schemas/`: Pydantic request/response and agent-facing data contracts. Do not place database queries here.
- `services/`: user-scoped application behavior, domain validation, publication, and read models.
- `models/`: SQLAlchemy persistence definitions and enums. Schema changes require Alembic migrations.
- `jobs/`: durable enqueueing, scheduling, leasing, retries, and handler integration.
- `agents/`: Otari client, prompts, structured contracts, evidence validation, cost handling, and orchestration.
- `security/`: reusable trust-boundary checks such as CSRF and outbound URL validation.

Dependencies should generally point inward from `api` and `jobs` toward services and explicit protocols. Avoid importing HTTP concerns into services or ORM models into frontend-facing code.

## Request and persistence rules

- Use `DbSession`, `CurrentUser`, `CurrentSession`, and `CsrfRequired` from `api/deps.py`.
- `session_dependency` commits successful requests and rolls back exceptions. Do not add service-level commits to request-scoped operations.
- Scope every user-owned lookup and mutation by `user.id`, including nested resources. A record owned by another user should be indistinguishable from a missing record.
- Use the registered RFC 9457-style `application/problem+json` handlers. Return safe details and preserve `request_id` correlation.
- Validate submitted external URLs with the existing public-HTTPS resolver before fetching or approving them.
- Keep test-only injection and authentication behind `testing=True` and `ENVIRONMENT=test`.

## Jobs and agent runtime

- Enqueue jobs in the same transaction as the state change that requires them.
- Use stable deduplication keys and design handlers for retries, lease renewal, and interrupted-run recovery.
- Keep job payloads small, JSON-safe, and identifier-based; reload authoritative state inside the handler.
- Preserve configured task, search, token, deadline, concurrency, confidence, and cost ceilings.
- Do not weaken structured-output validation, evidence scope validation, prompt-injection defenses, or publication grounding.
- Keep the worker at one production replica until the process-local Otari semaphore is replaced with shared coordination.

## Migrations

Follow `migrations/README.md`. Review autogenerated SQL, constraint names, indexes, defaults, nullability, data backfills, and downgrade safety. Test against PostgreSQL rather than SQLite.

## Tests

- Put pure domain and boundary cases in `tests/unit/`.
- Put database, routing, transaction, auth, user-isolation, and job-lease behavior in `tests/integration/`.
- Keep provider protocol fixtures in `tests/contract/` and deterministic agent quality/security checks in `tests/evals/`.
- Normal tests must use fake clients and fixtures. Never make paid provider calls as an incidental test side effect.

Start with focused tests, then run the backend verification commands from the root `AGENTS.md`.
